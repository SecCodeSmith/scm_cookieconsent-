## Departures from the design (implementation, 2026-11-16)

- D2 order: the script is requested first, then the consent `update`, then the tag start commands (`gtm.start` / `js` / `config`), then `scm_consent_update`, then the queue. The design lists `loadTags` (including the start commands) before the update; pushing a direct-mode `config` before the update would make gtag.js evaluate its `page_view` with every signal still denied, which is the cookieless ping basic mode must not send. The observable spec order (tag requested, update applied, events after both, `scm_consent_update` before the events) is unchanged.
- `SCM_GCM.ready` now means "a grant exists and its tag step has run" (also when Consent Mode is disabled or no id is configured: events then go to the dataLayer in mode `none`, as in 1.8.0, but only after a grant).
- D7 / 3.1: sticky buttons instead of a banner without any internal scroll (see 3.1).
- New `SCM_EC.cartId` (server) supplies the cart id for the `begin_checkout` guard.
- `tests/unit/` (harness, minified-copy check) is committed; the earlier changes kept their harness in a scratch folder. CI got a `js-harness` job.
- `tests/e2e/specs/01-upgrade.spec.js` pins the 1.7.0 commit (`b7ce1d8`) because HEAD already carries 1.8.0; `.gitattributes` forces LF for `*.sh` (a CRLF checkout broke `stack.sh` in WSL).
